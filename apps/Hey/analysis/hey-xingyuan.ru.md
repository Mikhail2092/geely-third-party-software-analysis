# Отчет о статическом анализе разблокированной версии Hey v1.2.4 Xingyuan

## 1. Назначение и выводы

Строка `синъюань` в имени файла образца — приблизительная кириллическая транслитерация названия «Xingyuan». С учетом контекста головного устройства в отчете используется сокращенное название «версия Xingyuan». Связь с этой моделью автомобиля является семантическим выводом из имени файла; код APK не содержит открытой константы названия модели.

Основные выводы:

- **Подтверждено хешами отдельных файлов**: за исключением трех групп `dimens.xml`, компилируемых в `resources.arsc`, версия Xingyuan и стандартная разблокированная версия имеют одинаковые `classes.dex`, все Native-файлы `.so`, XML компоновки, изображения и остальные декодированные ресурсы. Поэтому их бизнес-функции, протоколы и изменения лицензирования совпадают.
- **Подтверждено Manifest**: версия Xingyuan дополнительно объявляет `android.permission.INTERNAL_SYSTEM_WINDOW`; все остальные компоненты приложения и разрешения совпадают.
- **Подтверждено структурированными различиями ресурсов**: отличаются только собственные размеры приложения в `values/dimens.xml`, `values-sw1000dp/dimens.xml` и `values-sw1400dp/dimens.xml`. Размеры главного экрана, панелей, диалогов и текста в основном уменьшены примерно до 70% от стандартной версии, а размеры страницы активации по умолчанию — примерно до 50%.
- **Обоснованный вывод**: этот вариант предназначен для головного устройства с иными DPI/размерами окна или требованиями к системному окну. Это версия адаптации отображения, а не отдельная функциональная ветвь.

## 3. Точные отличия от стандартной разблокированной версии

### 3.1 Manifest

Единственное различие декодированного Manifest — добавленное в версии Xingyuan разрешение:

```xml
<uses-permission android:name="android.permission.INTERNAL_SYSTEM_WINDOW"/>
```

Новые Activity, Service, Receiver, Provider или Intent Filter не добавлены.

## 4. Функциональная реализация

Все перечисленные ниже функции реализованы тем же кодом DEX/Native, что и в стандартной версии. Это фактические функции версии Xingyuan, а не выводы из имени файла.

### 4.1 Громкая связь в реальном времени

- Короткое нажатие запускает 60-секундный обратный отсчет громкой связи; повторное нажатие может завершить его раньше.
- Длительное нажатие включает непрерывную громкую связь; повторное нажатие завершает ее.
- Используются захват микрофона в реальном времени, программные DSP/изменение голоса и воспроизведение по заданному автомобильному аудиомаршруту.
- Интерфейс показывает кольцо обратного отсчета, световой аудиоэффект, текст состояния и перетаскиваемый ползунок усиления.

### 4.2 Параметры аудио и DSP

| Параметр | Реализация/значение по умолчанию |
|---|---|
| PCM | 48 кГц, 16 бит, один канал |
| Источник записи | По умолчанию `7`, можно изменить |
| Audio usage | По умолчанию `73`, для тестового воспроизведения можно перебрать `0..100` |
| Маршрутизация устройств | Можно указать ID входного/выходного `AudioDeviceInfo` |
| Усиление | По умолчанию `5.0`, можно настроить нижнюю и верхнюю границы |
| Полосовой фильтр | По умолчанию `300..4000 Hz`, включен по умолчанию |
| Шумовой порог | Можно включить; интенсивность по умолчанию `0.5` |
| AGC | Можно включить |
| Сдвиг частоты | Можно включить; по умолчанию `5 Hz` |
| Реверберация | Нет/умеренная/сильная |
| Изменение голоса | Исходный/низкий мужской/высокий женский/робот/электронный |
| Аппаратный DSP | Ecarx workmode: выкл./шумоподавление/эхоподавление/оптимизация пробуждения |

`libvoiceeffect.so` реализует пять уровней изменения голоса Native. Уровень Java объединяет усиление, фильтрацию, шумовой порог, AGC, реверберацию и сдвиг частоты.

### 4.3 TTS, запись и музыка

- Сохраняется до 20 быстрых элементов текста или записи WAV.
- Android TTS поддерживает регулировку скорости речи, высоты тона и громкости.
- Записи сохраняются как `Download/Hey/recordings/rec_yyyyMMdd_HHmmss.wav`; их можно воспроизводить, переименовывать и удалять.
- Каталог музыки по умолчанию — `Download/Hey/music`; поддерживаются MP3/WAV/FLAC/OGG/M4A/AAC/WMA.
- Музыка поддерживает воспроизведение/паузу, предыдущую/следующую композицию, позицию, повтор списка и повтор одной композиции. При ошибке `MediaPlayer` используется резерв `MediaExtractor`/`MediaCodec`.
- TTS, записи и музыка используют общие настраиваемые usage/устройство автомобильного вывода и сеанс усилителя.

### 4.4 Быстрый запуск и отладка

- Доступна перетаскиваемая плавающая кнопка с сохранением положения, размера и прозрачности.
- Длительное нажатие кнопки OK на руле запускается через локальный VHAL gRPC.
- Поддерживается автоматический запуск по ключевым словам журнала.
- Можно настроить автоматическую громкую связь после нажатия значка, а также открытие/воспроизведение заданного элемента TTS или музыки по умолчанию.
- Страница отладки может перечислять аудиоустройства, воспроизводить тестовый тон 440 Hz, перебирать usage, показывать форму сигнала микрофона, тестировать громкую связь, запрашивать/задавать группы громкости и управлять внешним усилителем. Показываемое состояние усилителя считывается из состояния управления внутри процесса, а не из фактического аппаратного состояния HIDL.
- Встроенный клиент ADB TCP может подключаться к локальному порту `:5555`; он используется в основном как резервный канал настройки головного устройства, например Ecarx DSP workmode.

## 6. Ключевые протоколы

### 6.1 Intent/широковещательные сообщения

- `com.kooo.hey.action.START_TALK`
- `com.kooo.hey.action.STOP_TALK`
- `com.kooo.hey.action.TOGGLE_TALK`
- Внутренние эквиваленты: `com.kooo.hey.START_TALK`, `STOP_TALK`, `TOGGLE_TALK`
- Остановка музыки: `com.kooo.hey.music.STOP`

### 6.2 VHAL gRPC

| Поле | Значение |
|---|---|
| Адрес | По умолчанию `localhost:40004`, plaintext |
| Metadata | `session_id=<UUID>`, `client_id=hey_app` |
| Сервис | `vhal_proto.VehicleServer` |
| RPC | `StartPropertyValuesStream`, `SendAllPropertyValuesToStream`; также создается дескриптор `SetProperty` |
| Целевое свойство | По умолчанию `0x21407439` |
| Условие запуска | Первое `int32Values == 4` |
| Обработка разрыва | Закрытие channel и повторное соединение через 3 секунды |

### 6.3 Внешний усилитель ECARX

- Сервис HIDL: `vendor.ecarx.xma.audiocontrol@1.0::IEcarxAudioControl/default`.
- Код транзакции по умолчанию: `55`, настраиваемый.
- `int32=1` включает, `int32=0` выключает.
- Этот специализированный путь управления используется только для usage `72`; усилитель отключается через 60 секунд после освобождения всех сеансов.

### 6.4 HTTP/JSON

| Функция | Метод | Основные поля |
|---|---|---|
| Автоматическая активация | `POST getAutoActivateUrl()` | `device_id`, `device_model`, `app_version`, необязательный `cert_sha256`, `android_version`, необязательный `serial_no` |
| Подтверждение переноса | `POST <server>/api/migration/confirm` | Приведенные выше поля устройства с условными сертификатом/SN + `migration_token` |
| Heartbeat | `POST getHeartbeatUrl()` | Устройство/версия/время и условные сертификат/SN; локальное ограничение до одного раза в 12 часов |
| Повторная проверка черного списка | `POST <server>/api/check-blacklist` | `device_id`; при HTTP 200 считывается `blacklisted`; состояние активации очищается только после двух истинных результатов с интервалом 2 секунды |
| Отправка журнала | `POST <server>/api/upload-log` | `device_id`, `device_model`, `app_version`, `nickname`, `description`, `content`; при отсутствии псевдонима/описания записываются пустые строки |

URL сервисов предоставляет `libheylicense.so` в разделенном/закодированном виде. Сетевая конфигурация явно разрешает открытый HTTP для поддоменов `suyunkai.top`; QR-код покупки использует `https://coauto.cc/`.

## 7. Изменения разблокировки

Логика разблокировки в образце Xingyuan полностью совпадает со стандартным образцом:

- `defpackage.match.m1148final()` напрямую задает статический результат активации true, значение сеанса `1`, а затем возвращает `true`.
- `defpackage.match.m1143case(code)` также напрямую возвращает `true`.
- Начальная неактивированная ветвь `MainActivity.onCreate()` пропускается из-за указанного выше фиксированного истинного пути.
- `MainActivity.onResume()` по-прежнему вызывает `NativeBridge.validateSession(1)` и открывает `ActivationActivity`, когда возвращается `0`.
- Корутина запуска по-прежнему выполняет две проверки черного списка; только два результата `blacklisted=true` очищают состояние активации и открывают страницу активации.
- Код автоматической активации, переноса, heartbeat, черного списка и удаленной конфигурации полностью сохранен.

Таким образом, «Xingyuan» и «разблокированная» — два независимых измерения: первое означает адаптацию UI/окна, второе — то же изменение потока управления лицензированием, что и в стандартном варианте. Статически зафиксированную истинность начальной проверки нельзя дополнительно описывать как «страница активации никогда не открывается при любом нормальном запуске».

## 8. Локальные данные

- `hey_config`: аудио, DSP, изменение голоса, TTS/музыка, плавающее окно, триггеры и действия запуска.
- `hey_hb/last_ts`: ограничение частоты heartbeat.
- `log_upload/device_nickname`: сведения интерфейса отправки журналов.
- `current_session.log` / `previous_session.log`: ротация журналов сеанса приложения.
- `Download/Hey/music`: каталог музыки по умолчанию.
- `Download/Hey/recordings`: записи WAV.
- `adb_private_key` / `adb_public_key`: ключи аутентификации встроенного клиента ADB TCP.

Различия размеров интерфейса хранятся в таблице ресурсов APK и не являются переключателем SharedPreferences времени выполнения.

## 9. Связи с другими программами

- **Стандартная разблокированная версия Hey**: те же имя пакета, версия, DEX, Native-код и сертификат; непосредственное отношение замены.
- **EVCC/EVCC mini**: текущие образцы имеют общий сертификат повторной подписи и пространство имен `com.kooo.*`, а Hey и EVCC используют общий домен продуктового сервиса `coauto.cc`. Hey не привязывает сервис EVCC и может работать независимо.
- **AutoAudio/AutoDisplay/AutoService**: отсутствуют связи вызовов через запрос пакета, AIDL, Intent или Provider; с AutoAudio совпадает только функциональная область автомобильного аудио.

## 10. Границы статического анализа

- Тестирование на головном устройстве Xingyuan не выполнялось, поэтому точное влияние `INTERNAL_SYSTEM_WINDOW` на целевую прошивку нельзя подтвердить только по APK.
- Проверка Native-сеанса и повторная проверка черного списка при запуске все еще могут открыть страницу активации; итоговую ветвь запуска для конкретного устройства и состояния сервера статически подтвердить нельзя.
- Пропорции масштабирования ресурсов подтверждаются, но физическое разрешение и Android density целевого головного устройства нельзя определить только по статическим ресурсам.
- Математические параметры Native-изменения голоса и полный разделенный URL в Native-библиотеке лицензии не удалось полностью восстановить с уровня Java.
- Заглушки больших обфусцированных R8-методов в default JADX покрыты представлением simple и smali. Ключевые gRPC property/value, таблица различий, ветви лицензирования и автомат состояний talk проверены.

## 12. Проверка восстановления пробелов JADX

Стандартный структурированный вывод версии Xingyuan содержит 165 заглушек `Method not decompiled` в 125 Java-файлах. Полный вывод simple содержит 1,530 Java-файлов; остаются только четыре заглушки методов фреймворка/вспомогательных методов, покрытые smali.

Семь непосредственно не обработанных бизнес-методов и соответствующие smali-файлы версии Xingyuan и стандартной версии имеют одинаковые SHA-256 каждого файла. Восстановленное содержимое включает отладочную консоль и сохранение конфигурации, переключение разделов запуска, повторную проверку активации/session при возврате на передний план, автомат непрерывного/60-секундного talk, перебор Audio usage и инструмент команд групп громкости Android Car.

Поэтому вывод о различиях вариантов не меняется: обе версии используют один бизнес-DEX, а различия версии Xingyuan по-прежнему сосредоточены в разрешении Manifest и калибровке размеров ресурсов.
